# Developer Documentation

## Design Goals

- Keep the original token image unchanged.
- Draw death-state visuals as non-interactive PIXI children of the token.
- React to D&D5e actor data changes without requiring manual refreshes.
- Avoid duplicate status ActiveEffects when applying `Dead`.
- Preserve compatibility with worlds that used older local versions of the module.
- Keep release packaging reproducible through `git archive`.

---

## Runtime Architecture

### Main script

```text
scripts/dnd5e-death-token-effects.js
```

### Relevant actor paths

```text
system.attributes.hp.value
system.attributes.death.failure
```

### Main visual elements

- Overlay icon: `PIXI.Sprite`
- Token border: `PIXI.Graphics`
- Both are added as children of the token and marked as non-interactive.

---

## Hooks Used

- `init` — register world settings.
- `ready` — run migrations and register runtime hooks.
- `updateActor` — refresh tokens when HP or death failures change.
- `updateToken` / `createToken` / `drawToken` — refresh a token when it appears or changes.
- `deleteToken` — remove orphaned visuals.
- `refreshToken` — reposition existing visuals.
- `createActiveEffect` / `updateActiveEffect` — remove Bloodied after Dead if needed.
- `canvasReady` — refresh scene tokens.

## Release Workflow

Recommended clean release:

```bash
python dev-tools/buildScripts/build_release.py
```

Local test with uncommitted changes:

```bash
python dev-tools/buildScripts/build_release.py --allow-dirty
```

Expected output:

```text
dist/dnd5e-death-token-effects-<version>.zip
dist/dnd5e-death-token-effects.zip
```

The non-versioned ZIP must exist because `module.json` uses the release URL:

```text
https://github.com/foundryvtt-sinregistrar/dnd5e-death-token-effects/releases/latest/download/dnd5e-death-token-effects.zip
```

---

## Release Checklist

1. Update `module.json` version.
2. Move entries from `[Unreleased]` to the new version in `CHANGELOG.md`.
3. Run the build script locally.
4. Commit using a Conventional Commit style message.
5. Create a tag matching `module.json`, for example `v1.14.1`.
6. Push `main` and the tag.
7. Review the draft release generated by GitHub Actions before publishing.

---

## Commit Convention

Recommended style:

```text
feat(settings): add configurable death overlay color
fix(status): prevent duplicate dead active effects
build(release): add release packaging workflow
docs(readme): document manifest installation
compat(foundry14): verify module against Foundry 14.363
```
